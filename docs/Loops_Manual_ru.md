# Руководство пользователя библиотеки Loops 

## Назначение Loops

Loops - это маленький и быстрый JIT-компилятор, оформленный в виде высокоуровневой C++ библиотеки. Он кросс-платформенный, поддерживает разные 64-битные архитекутры процессоров, разные операционные системы и компиляторы. Интерфейс библиотеки имитирует исполняемый код, что снижает порог вхождения. Акцент сделан на векторизованном коде, основное предназначение библиотеки - писать вычислительно-тяжёлые векторизованные ядра. Работа с библиотекой напоминает работу с векторными интринзиками.<br/><br/>
Возможность собирать нужный код на лету, позволяет собирать оптимальные ядра для любого набора параметров(например, слои нейронных сетей), а так же склеивать циклы ядер, когда уже известно, в какой последовательности они будут вызываться, что позволяет избежать лишних прокачек данных через кэш. Иными словами, основное назначение проекта - ручная оптимизация.<br/><br/>
Проект вдохновлён xbyak. Xbyak - это JIT-_ассемблер_, тогда как loops - это JIT-_компилятор_. Два главных преимущества loops - это автоматическое распределение регистров и кросс-платформенность.

## Совместимость 
Поддерживаемые архитектуры процессоров:
* Aarch64. Векторное расширение - NEON.
* x86_64. Векторное расширение - AVX2.
* Risc-V64. Пока вектора не поддерживаются, запланированны в средней перспективе.

Поддерживаемые операционные системы.
* Linux: Aarch64, x86_64, Risc-V64.
* MacOS: Aarch64.
* Windows: x86_64.

Понятно, собрать библиотеку могут многие компиляторы и версии компиляторов. Ниже приведены лишь _верифицированные_ поддерживаемые компиляторы:
* gcc(DUBUG: get version) 
* clang(DUBUG: get version) 
* MSVC for Visual Studio 2019, Visual Studio 2022

## Скачивание, сборка и запуск примеров
### Linux и Macos 

На компьютере должны быть установлены git, CMake и C++ компилятор. 
1. Скачайте loops с git и войдите в диеркторию:
```
git clone https://github.com/4ekmah/loops
cd loops
```
2. Создайте сборочный каталог и сконфигурируйте проект:
```
mkdir build
cd build
cmake -DCMAKE_BUILD_TYPE=Release ../
```
3. Соберите проект:
```
make -j8
```

### Windows 

На компьютере должны быть установлены VSCode, CMake и Visual Studio, или отдельно Visual Studio Build Tools(https://aka.ms/vs/stable/vs_BuildTools.exe). Также нужно добавить в VSCode расширение для CMake.

git clone https://github.com/4ekmah/loops

## Базовые понятия
Рассмотрим интерфейс библиотеки и способы работы с ней.
### loops::Context, loops::Func

Поскольку мы собираем функции во время исполнения программы - нужно какое-то место, где мы будем их хранить. **loops::Context** - это такое хранилище функций, как правило, создаётся единожды, **loops::Func** - репрезентирует отдельно взятую функцию и позволяет получить указатель на неё. <br/><br/>
Рассмотрим упрощенный интерфейс loops::Context. 
```
class Context
{
public:
    Context();
    virtual ~Context();
    void getFuncs(std::vector<Func>& funcs);
    Func getFunc(const std::string& name);
    bool hasFunc(const std::string& name);
    std::string getPlatformName() const;
    int vbytes() const;
    template<typename _Tp> inline int vlanes() const;
    void compileAll();
    std::vector<std::string> get_all_passes();
};
```
Класс представляет из себя умный указатель, поэтому опреации копирования, присваивания, перемещения не вызывают никаких заметных перемещений данных. При окончательном удалениии память, выделенная под функции деаллоцируется, а значит, все указатели на функции становятся недействительными. **Context**, как и loops в целом не является thread-safe, поэтому вопросы синхронизации возлагаются на пользователя библиотеки. <br/><br/>
Основное назначение контекста - быть контейнером для функций. Доступ производится по именам, которые задаются при определении очередной функции с помощью методов **getFunc**, **hasFunc**, либо с помощью доступа к вектору функций с помощью метода **getFuncs**.<br/><br/>
Кроме этого **Context** позволяет получить информацию о платформе, на которой происходит сборка, от которой может зависеть генерируемый код:
* **getPlatformName** - название архитектуры. Может принимать значения: "AArch64", "Intel64" или "Risc-V".
* **vbytes** - размер векторного регистра в байтах. К примеру, 16 байт на Arm, 32 байта на Intel. 
* **vlanes** - количество элементов данного типа в векторном регистре.
###
С помощью метода **compileAll** можно добиться одновременной компиляции всех описанных в контексте функций, что может быть полезно. Метод не обязательный, при  получении указателя на функцию компиляция так или иначе произойдёт.
<br/><br/>
Метод **get_all_passes** выдаёт список названий компиляторных проходов. Указывая такое имя в методе **Func::printIR**, можно распечатать код после выполнения конкретного прохода, что может быть полезно для отладки.
<br/><br/>
Рассмотрим теперь упрощенный интерфейс **loops::Func**.
```
class Func
{
public:
    Func();
    virtual ~Func();
    std::string name() const;
    void* ptr();
    enum { PC_OPNUM = 1 , PC_OP = 2, PC_HEX = 4 };
    void printIR(std::ostream& out, int columns = PC_OPNUM | PC_OP, const std::string& passname = "") const;
    void printAssembly(std::ostream& out, int columns = PC_OPNUM | PC_OP | PC_HEX) const;
};
```
Так же, как и **loops::Context**, класс **loops::Func** - умный указатель. Копирование, перемещение - дешёвые операции.
<br/><br/>
Есть два метода для печати кода функции:
* **printAssembly** распечатывает ассемблерное представление функции на текущей архитектуре.
* **printIR** распечатывает кросс-платформенное промежуточное представление. С помощью аргумента **passname** можно выбрать проход, после которого будет распечатан IR.
###
Оба метода позволяют с помощью поля **columns** настроить столбцы выводимых данных:
* **PC_OPNUM** - номер строки с двоеточием 
* **PC_OP** - инструкция
* **PC_HEX** - шестнадцатеричное представление закодированной инструкции 
###
Наиболее важной функцией явлется функция **ptr**, с помощью которой можно получить указатель на скомпилированную функцию, преобразовать его к указателю на функцию нужного вида и вызвать. Есть две возможных сигнатур loops-функций:
```
void func(int64_t a0, int64_t a1, ...)
```
или 
```
int64_t func(int64_t a0, int64_t a1, ...)
```
Т.е, возрат либо **void**, либо **int64_t**, а в качестве аргументов могут передаваться от нуля до бесконечности 64-битных значений. Никто вам не помешает передавать double или, что особенно важно, любой указатель, потому что указатели - 64-битные.
<br/><br/>
**NOTE:** на всякий случай, несмотря на запись выше, речь не идёт про variadic-функции с переменным числом аргументов. Каждая скомпилированная loops фукнция имеет конкретное число переменных.
### Макросы
Программист на loops знимается метапрограммированием, то есть пишет программу, которая пишет другую программу. Нашей задачей было сделать метапрограммирование максимально приближенным к обычному программированию. Для наиболее полной имитации обычного написания программы используются макросы, позволющие имитировать объявление функции, ветвления, циклы, и прочие управляющие конструкции.
<br/><br/>
Например, рассмотрим генерацию самой простой функции, складывающей два числа:
```
#include "loops/loops.hpp"
#include <iostream>
int main()
{
    loops::Context CTX; 
    USE_CONTEXT_(CTX);
    loops::IReg a, b;
    STARTFUNC_("sum", &a, &b)
    {   
        loops::IReg c = a + b;
        RETURN_(c);
    } 
    loops::Func sfunc = CTX.getFunc("sum");
    typedef int64_t (*sum_t)(int64_t a, int64_t b);
    sum_t func = (sum_t)sfunc.ptr();
    std::cout << func(5, 4) << "\n";
    return 0;
}
```
Все имена с большими буквами и подчеркиванием на конце здесь - это макросы.
Список всех макросов loops:
* **USE_CONTEXT_(ctx)** - активирует систему макросов в текуще базовом блоке, привязывая её к теущему контексту.
* **STARTFUNC_(name, &arg0, &arg1,... )** - порождение функции с заданным именем и набором аргументов, которые будут в неё передаваться. В последующих фигурных скобках заключено тело порождаемой функции.
* **CONST_(x)** - порождение скалярного регистра с инициализацией его заданным значением и привязкой регистра к текущей функции. Пример использования: 
```
    IReg i = CONST_(0); 
```
* **VCONST_(type, x)** - порождение векторного регистра с инициализацией всех его элементов заданным значением и привязкой регистра к текущей функции. Пример использования: 
```
    VReg<float> pi = VCONST_(float, 3.141528f); 
```
* **DEF_(x)** - декларация скалярного регистра без инициализации значением, с привязкой регистра к текущей функции. Пример использования: 
```
    IReg i = DEF_(); 
```
* **VDEF_(type)** - декларация векторного регистра без инициализации значением, с привязкой регистра к текущей функции. Пример использования: 
```
    VReg<float> a = VDEF_(float); 
```
* **IF_**, **ELIF_**, **ELSE_**, **WHILE_** - общеизвестные управляющая конструкция, которые в сгенерированном коде будут вести себя как и предполагается.
* **RETURN_** - возврат значения из функции.
* **BREAK_/BREAK_(levels)** - остановка и выход из цикла. Есть нетипичная вариация с укзанием уровня вложенности цикла, с которого нужно выйти. Пример:
```
    WHILE_(i < 100)
        WHILE(j < 100)
        {
            IF(/*condition*/)
                BREAK_(2); //Выход из цикла WHILE_(i < 100)
        }  
```
* **CONTINUE_/CONTINUE_(levels)** - переход к следующей итерации цикла. Есть нетипичная вариация с указанием уровня вложенности цикла, на котором нужно начать следующую итерацию.
